# docs/

## Purpose

## For AI Agents

### Working In This Directory

- Документы описывают **целевое состояние** платформы, а не текущее (проект Pre-MVP). Различай «что запланировано» и «что уже реализовано».
- `domain-model.md` — источник правды для имён сущностей, полей, ID-форматов и связей. При генерации кода синхронизируйся с ним.
- `technical-structure.md` раздел 12 содержит план фаз; прочитай его, чтобы понять, что должно быть готово сейчас (Фаза 0: домен и контракты).
- При изменении архитектурного решения — сначала создай ADR в `adr/`, затем обновляй документацию.
- **Документацию обновляют в том же PR что и код**: при значимых изменениях кода актуализируй соответствующий doc-файл в том же коммите/PR.
- Не редактируй принципиальные части (стек, бизнес-модель, ЦА) без согласования с product owner'ом.
- Диаграммы — только Mermaid или SVG (не бинарные форматы). Имена файлов — `kebab-case.md`.

### Testing Requirements

Документация не тестируется автоматически, но при PR проверяется:
- Корректность ссылок между файлами
- Соответствие имён сущностей `domain-model.md`
- Актуальность списка ADR в `adr/README.md`

### Common Patterns

- ID-форматы: `{тип}_{ULID}` (например, `app_01HQ8X4Z...`, `per_01HQ8X4Z...`)
- Деньги — в копейках (integer), никогда float
- Даты — UTC ISO 8601
- Статусы enum — snake_case (например, `auto_approved`, `manual_review`)
