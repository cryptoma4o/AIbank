# docs-parsing eval corpus

Синтетический корпус для оценки качества парсинга документов агентом `agent-document-intake`.

## Состав v1

| Файл | Кейсы | Тип | Цель |
|---|---|---|---|
| `passport-cases.json` | 25 | Паспорт РФ | Извлечение ФИО, серии/номера, кода подразделения, даты рождения, адреса регистрации |
| `charter-cases.json` | 25 | Устав ООО | Извлечение наименования, ИНН, ОГРН, директора, уставного капитала, ОКВЭД |

Итого 50 кейсов.

## Метрики

Скоринг кейса — `field_coverage`:

```
score = matched_fields / total_expected_fields
```

Кейс считается `pass` при score ≥ 0.8 (см. `harness/runner.py`).

## Источник данных

Все кейсы **синтетические**. Никаких реальных ПДн. Использован `tools/data-generator/` для:

- Валидных ИНН с корректным контрольным разрядом
- Валидных ОГРН
- Реалистичных адресов (формат ФИАС)
- Случайных серий/номеров паспортов в допустимых диапазонах

Сами scan'ы документов в этой версии корпуса **не приложены** — поле `document_url`
указывает на placeholder `fixtures://...`. До интеграции реальных PDF/PNG fixtures
runner должен либо мокировать ответ агента, либо сам агент должен подменять ввод
на тестовые сэмплы при `?mode=eval` параметре.

## Owner

ML-инженер + банковский эксперт (ADR-0012, см. также `docs/technical-structure.md` § 7.5).
До назначения owner'а корпус считается v0 — не используется как gating-критерий.

## Запуск

```bash
cd ai/eval-harness
python -m harness.cli run datasets/docs-parsing/passport-cases.json --agent-url http://localhost:8101
python -m harness.cli run datasets/docs-parsing/charter-cases.json --agent-url http://localhost:8101
```

## Расширение

Новые кейсы добавляются через PR с пометкой `eval-corpus`. Изменение существующих
кейсов запрещено без обоснования (метрики потеряют сравнимость во времени).
Нумерация — последовательная (`passport-026`, `charter-026`).
