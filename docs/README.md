## Принципы документации

- **Markdown-only.** Все документы — `.md`, версионируются вместе с кодом в Git
- **Жить с кодом, не отдельно.** При значимых изменениях кода обновляется и документация в том же PR
- **Решения — в ADR.** Изменения архитектуры не делаются «на словах»; сначала ADR с обсуждением, потом код
- **Рисунки — в Mermaid или SVG.** Никаких бинарных диаграмм, потерянных через год
- **Каждый документ имеет owner-а** (см. ниже)

## Ownership

Без выделенных владельцев документы превращаются в мусор за полгода. Закрепляем ответственность с первого дня:

| Документ | Owner |
|---|---|
| product-vision.md | Продакт-менеджер |
| technical-structure.md | Главный архитектор |
| ai-agents-automation.md | ML-лид + банковский эксперт |
| domain-model.md | Главный архитектор |
| compliance-map.md | Юрист по банковскому праву + комплаенс-эксперт |
| security-architecture.md | Security-инженер |
| tenant-configuration.md | Тех-лид платформы |
| adr-template.md | Главный архитектор |

Owner — не значит «единственный, кто пишет», но значит «отвечает за актуальность и качество».

## Жизненный цикл документа

1. **Draft** — есть в репо, но помечен `Status: Draft`. Для обсуждения, не для имплементации
2. **Active** — основной рабочий документ, обновляется по мере развития проекта
3. **Deprecated** — документ устарел, заменён другим (или функционал убран)

## Соглашения

- Документы — на русском (рабочий язык команды), технические термины — на английском там, где это естественно
- Названия файлов — `kebab-case.md`
- Каждый документ начинается с краткого описания назначения
- Версионирование документов — через Git, без явных версий в файлах
- При значимых изменениях — упоминание в `CHANGELOG.md` репозитория

## Как использовать новому члену команды

День 1: прочитать `product-vision.md` (час), `technical-structure.md` (2 часа), пройтись по `domain-model.md` (час)
День 2-3: углубиться в свою область — backend → `tenant-configuration.md` + `adr/` папка; ML → `ai-agents-automation.md`; security → `security-architecture.md` + `compliance-map.md`
Неделя 1: задать вопросы в командный чат, обновить документ, где нашли неточность

## Что НЕ в этой документации

- Спецификации внутренних API (живут в `services/*/openapi.yaml`)
- Runbook-и операционных процедур (живут в `docs/runbooks/`)
- Детальные дизайны UI (в Figma + ссылки в product-vision.md)
- Тарифы и коммерческие условия (отдельно, не в публичной документации)
